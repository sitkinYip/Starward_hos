# 头像 Picker 过滤：真机操作与判定

本文是操作步骤，**不是已执行报告**。当前没有能够证明 Picker 全量结果的布局/窗口证据，不能因某张截图没有负例就标“过滤通过”。不修改 App 过滤参数，也不以主机直接上传代替系统选图。

输入均保留私有：

- 正控：`artifacts/private/profile-device/avatar-import-receipt.json`，原生主四象限 PNG；源/导出 SHA 应相同。
- 负控：`artifacts/private/profile-device/filter-import-receipt.json`，分别按 sourceSha256 对应 `artifacts/private/profile-filter-fixtures/manifest.json`。
- 超限 PNG 原始字节数应为 **52,428,801**，即 50 MiB + 1；GIF 是允许集合 JPEG/PNG/WebP 之外的格式。须核私有回执的实际导出 SHA/字节数，导入成功不代替 Picker 验收。
- 正式图片文件名、媒体 URI、当前用户目录均从这些私有回执读取，不抄到公开报告，也不猜用户 ID 或媒体资源 ID。

## 打开并确认当前系统表面

1. 在隔离账号的护照资料页点击“更换头像”。先确认当前窗口确为该调用打开的官方照片 Picker，记录实际窗口所属信息，不预设包名。
2. 用官方 `devecocli ui window list --all --format json` 与 `devecocli ui layout --format json --mode full` 捕获当前窗口及布局，原始输出放到新私有目录；截图也只存私有目录。不要把设备标识或个人图库缩略图复制到公开报告。
3. 正控必须可识别：使用精确文件名/媒体资产信息（如果当前系统布局实际提供），或经目视明确识别本项目四象限 QA 图。仅“Picker 打开了”不等于正控可选。

## 可接受的负例证据

优先采用当前实际 UI 能支持的方式，不能根据预想的系统界面编造节点或结果。

- **有真实文件名搜索且语义已确认时：** 先以正控完整唯一名称检索并得到对应 QA 图，记录该搜索确实按资产文件名工作。再分别检索两个负控的完整唯一名称，记录完整查询词、系统明确空结果/不可选状态及前后窗口布局；公开产物只留 SHA、用例类型和计数。最后重复正控检索，确认 Picker 仍可使用。若系统提供的是语义/内容搜索，无法确认文件名索引语义，不能据空结果判过滤通过。
- **负控在 Picker 中可见但被禁用时：** 只操作能明确映射至自有回执的 QA 图，记录其禁用状态/官方提示及无法进入裁剪或形成选择结果；同时记录正控能进入裁剪。应据实写“禁止选择/系统提示”，不能写成“素材完全未显示”。
- **具备可验证完整结果集时：** 必须证明结果范围、可识别资产与完整枚举边界，例如系统明确总数与逐页去重数量一致，并实际到达两端。布局字段应能把测试资产映射到导入回执。只有单屏可见区域、若干滑动截图、滑到最底部一次或按缩略图猜排序，都不能证明已完整排除负控。

不要为了补一个断言遍历或导出整个人图库。若上述方式都不能可靠建立结果范围或素材映射，应停止该负例的自动判定，保留实际窗口证据，并写：

> 正控选图已验证；超限/格式负控已导入并核 SHA。当前 Picker 可观测信息不足以确认完整过滤结果，负例过滤仍未验收。

这时可以另外记录“当前 HAP 已使用官方 fileSizeFilter 与 mimeTypeFilter，源码/编译核查通过”，但这不替代负例 UI 验收。

## 返回与不产生写入

- 检查期间不点资料保存。若正控进入裁剪，取消裁剪后应仍回到资料页，昵称和原有 pending 草稿按该用例保持，资料 PATCH 数不增加。
- 搜索/查看负控结束后取消系统 Picker；记录返回原资料页且没有新增资料 PATCH。用私有原始请求台账对比本次前后数量，不能把历史 PATCH 总数当本次写入。
- 主 PNG 与两个过滤负控的精确清理仍由其原始导入回执负责；不要使用 `mediatool delete all`、目录删除、通配符或按模糊文件名删除。

官方依据：项目已固定 API26；`devecocli docs read 开发指南/调测调优/调试命令/命令行工具/媒体库资源访问工具/mediatool`。该文档明确 query 按 display-name 查询媒体库、`-u` 返回资源 URI；**媒体库 query 不是 Picker 过滤查询**，不能混为同一个结果集。
