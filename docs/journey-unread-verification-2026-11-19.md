# 未读来信入口与轻提醒

本轮同时调整原生与 Web：答题浮标只承载未读，完整来信页保留历史；新来信在首页等页面用可关闭、可跳转的轻提示提醒。用户确认保留自动弹出未读信。只关闭不写已读，且本次场次不再反复自动弹出该封；明确确认且服务端保存成功才从未读列表移除。

底栏角标按用户反馈移到信封图标右上角，使用日间绿／夜间金主题，去掉默认红色描边。原生通过官方 FrameNode 的含变换坐标定位到图标，再显示不拦截手势的官方 Badge。通知反馈使用 HdsSnackBar 的查看和关闭按钮，正文也能点击前往来信。

| 范围 | 实际验证 |
| --- | --- |
| 初始状态 | 隔离 PocketBase 中一封已读、两封未读和一个已入场的双题场次。原生登录后数字角标为 2，没有将历史积压弹成新信 Toast。 |
| 新来信 | 通过隔离后端正式运营接口再发一封。首页 Toast 与角标更新，点查看进入「来信 → 旅途来信」。最终候选另验了点击 Toast 正文本身；点关闭则不跳转、不写已读，下一轮查询不重播。 |
| 自动及手动阅读 | 自动弹出保留。逐封普通关闭后，未读没有减少；下一轮轮询未重复弹出。点浮标显示三封未读，先前已读信没有混入；点开本身不写已读。 |
| 失败、重试与读完 | 对一条已读写入注入一次 503，信仍未读、错误与重试可达。重试及其余确认成功后未读变为 0，浮标收起，可点击提示前往历史。未提交答案保留。 |
| 夜间与拖动 | 直板真机核对金色角标、来信 Toast 和未读列表原图。带角标时官方底栏仍可从启程拖选到来信；浮标从信封中心直接拖动、贴边后不误开，轻点仍可打开列表。 |
| 前后台和退出 | 退到系统桌面后超过一个轮询周期，没有新增来信读取；后台发信，恢复前台能回源发现。退出后输入清空、无角标和旧 Toast、来信轮询停止。账号切换、迟到请求和暂停期间自动弹出记录由业务测试补充覆盖。 |

原生为 API 26、宽 387.692vp、density 3.25、fontScale 1 的直板机。系统栏透明；原始窗口 1260×2720px，可用内容高度 771.077vp。Web 同数据重放视口宽 388px，保留浏览器和系统栏的差别，不把全屏高度等同于原生可用内容高。三封未读及一封已读的原始 DTO 被单独冻结供 Web 对照；执行者实际看了同数据日间列表，以及两端各自的日夜角标、提醒和阅读状态。原生保留原有 ArkUI 弹层，Web 使用现有主题和列表排版，不声称两端像素完全一致。

原生测试的服务端基线是一次准备阶段入场、零次答题和一条旧已读记录。设备只新增三次成功的已读回执，另有一次预设 503；没有新增入场、答题、结算或领奖。用于主题及通知到达的后续合成信保持未读，不用修改历史数据造成功状态。

收尾已退出隔离账号，核对空输入及无来信轮询、角标和遗留提示，恢复系统主题和原左侧浮标位置。只移除了本轮的 USB 反向映射并停止临时 Docker 服务。最初采集器使用旧收件箱节点名导致等待失败，纠正为实际节点后复核了跳转；该采集器错误不记为业务通过。末候选另外验证了 Toast 正文点击和夜间浮标，核心未读业务未再改动。

运行固定工具链的 `scripts/hm.sh build`、`STARWARD_VALIDATION_DIR=artifacts/validation/journey-unread-20261119 scripts/hm.sh test` 和同变量的 `scripts/hm.sh lint`。业务测试实际 245 项通过；codelinter 无错误和警告，一项既有信纸模糊建议。SDK 签名、隔离包配置和安装启动分别核验，不修改生产包或 Push 配置。

隔离复现使用本机私有 `journey-unread-20261119/fixture.mjs` 启动 Docker PocketBase 和 HTTPS，只允许专用玩家的读取、登录、入场及通知确认路径。控制端通过本机 Unix socket 发合成信或设一次性故障。用 `configure-integration.py --endpoint https://127.0.0.1:18443 --ca <当次公开CA> --timeout-ms 3000` 配置独立构建目录，再用 `scripts/hm.sh run --skip-build` 安装；UiTest 操作及原始布局、DevEco CLI 截图与控制端台账相互核对。原始 DTO、账号材料和图像保留在忽略的私有目录。
