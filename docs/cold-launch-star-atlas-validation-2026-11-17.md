# 冷启星图过渡验收

本轮复用登录恢复页已有的星图和主题色作为系统冷启动画面。Web 无从控制原生应用启动窗；已有原生等待页是本轮视觉基准。启动窗由系统显示，已有的 ArkUI 环形动效在进入恢复页后继续，登录门禁和导航顺序沿用 A10。

| 场景 | 验收要求 |
| --- | --- |
| 日间、夜间冷启 | 在直板机上结束进程，从桌面打开同一候选包，检查启动窗显示相应主题的星图，交接到应用画面时不闪出旧方块图标或多一帧实色空白。区分桌面图标本身的系统过渡。 |
| 有会话，暂时等候 | 用独立 HTTPS 玩家延迟 `/me`。同一星图接上已有恢复页，系统状态栏与手势区域保持可见，恢复成功后可用。 |
| 无会话或服务端拒绝 | 按原有门禁进入登录或重试界面。启动图仅含公共品牌素材，快速结果不人为延迟。前后台恢复时不重播冷启页。 |
| 减少动画 | 系统窗展示静态素材；开启系统「减少动画」时，应用恢复页不转动外圈，仍能正常恢复或重试。 |

真机启动交接需要观察过程，而非只截启动完成后的首页。构建、签名、安装、画面与隔离网络各自记录。在开发候选的签名包中已核对解析后的配置和资源 ID，两张 PNG 的字节一致；这是打包证据。调试采样用官方 HDC 的离散截图，不采集音频。快捷采样无法证明每一帧不存在闪烁，也不能覆盖桌面启动动画。

配置依据：[官方增强启动页](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/launch-page-config) · [深浅色启动页资源](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/launch-page-resource-config)。固定 SDK `26.0.0.105` 的 `toolchains/modulecheck/startWindow.json` 包含所用字段。

启动图使用系统主题资源和画布颜色，按容器保持比例显示。两张 256×256 PNG 由 `scripts/render-start-window-atlas.py` 离线生成，沿用 `SessionAtlas` 的星轨几何和颜色资源，以及已有四角星矢量。桌面图标沿用自己的资源。无凭据或响应很快时，真正的登录或首页可以立即接替静态窗口，界面无需等待动画结束。

## 2026-11-17 直板机日间结果

同一签名候选包结束已有进程后，从系统桌面唯一匹配的「赴星之约」图标点开。一次采样清楚记录到桌面、系统静态星图、ArkUI 登录恢复页的顺序。系统星图在桌面启动动画的浅色圆角窗口内，已有转环和恢复文案随后显示。使用隔离网关暂时延迟真实 `/me`，验证恢复页没有显示私人内容，服务端返回后正常进入首页。每轮均为一次成功的认证 `/me`，期间没有业务写入。

首轮 `aa start` 只取得等待页，随后第一次桌面采样跨过了短暂系统窗，第二次调整采样相位后取得系统星图原图。离散截图能确认系统实际使用了新素材。夜间、系统减少动画、无会话桌面冷启和整个桌面动画逐帧效果仍需专项验收，已静态核验夜间素材打包。[日间桌面采样](../artifacts/validation/release-prep-20261117/cold-launch-desktop-light.json)

需要重新生成素材时，在装有 Playwright 和 Chromium 的 Python 环境中运行 `python3 scripts/render-start-window-atlas.py`。日常 DevEco 构建直接打包仓库中的 PNG，无需额外工具。
