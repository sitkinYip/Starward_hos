# Starward UI 还原

这是业务与版式迁移，不是重新设计。用户在2026-11-04确认了首组“侧栏头部/高度＋Rank留白”样板；后续自行逐点实现、自审、真机对照，仅会改变既定可见布局、交互或材质的替代方案再问，不为每屏增加审批。新薄封装、正常尺寸计算等普通实现选择自主完成。

先读项目[AGENTS.md](../../../AGENTS.md)、相应[逐状态验收表](../../../docs/feature-acceptance-matrix.md)。已确认尺度、已定位问题与首组命令见[UI复核记录](../../../docs/ui-parity-review-2026-11-04.md)。它们包含历史和待实现事项，不能把“已确认交互规则”当成“已实现”。

## 原生与还原的分工

- 保留Web的内容顺序、信息层级、中文文案、字体、字号/行高、内容宽度、留白、图标语义及状态行为。不能因使用系统组件而新增标题、摘要、进度块、常驻操作或空占位。
- 官方ArkUI负责容器、材质、反馈、系统交互与动画；通过`ui/`内的V2薄封装定制内容与样式。官方组件的默认标题/间距不自动成为产品设计。
- 用户已认可外层顶底栏位置、官方悬浮Tabs、触摸主题色流光、玻璃侧栏和按头像位置左右进入。系统状态栏/手势区及官方材质是批准差异；内容排版差异要单独审查。
- 沿用品牌令牌和已登记的NotoSerifSC展示字体。通用设计skill仅用于审查层级、换行、留白、对比度与可达性，不据其换字体、重配色或新增装饰。
- 字号和行数相同仍可能换行不对。题卡标题的Web `text-wrap: balance`已用官方Text `lineBreakStrategy(BALANCED)`对应；保留默认BREAK_WORD，不插入换行或调小字体掩盖末字孤行，长短及隐藏题名均看实际原图。
- 官方能力不适配业务时可组合基础ArkUI组件。先核API26 SDK和官方文档；需要改变已定交互、布局或材质时，带具体差异询问用户，不凭猜测替代。

## 每个小点如何推进

1. 定义本次页面/状态与边界，先更新验收表。列出Web内容和已批准原生差异；不扩成无关的大回归。
2. 用冻结Web源码及正式路由确认实际结构和手机媒体查询；checkout与线上版本分开记。正文、表单、选中/只读/错误等状态都从真实组件与契约确认，不从单张截图猜字段。
3. 使用同数据：优先使用本轮已授权的完整内容快照，新增生产连接或凭据读取仍遵守实际授权范围；玩家状态和写入来自明确隔离环境。保留session→level→question关联及原始presentation，区分缺失、false和空值。真实题目不是数据库内部title的逐字展示。
4. 基于官方组件实现，并按本次实际状态自审：元素是否多/少、字号/行高/换行、外内边距、安全区、键盘、返回/关闭、草稿/焦点及动画中断。保持账号代次、请求身份、重试与服务端权威边界。
5. 构建、lint及本次相关测试完成后，用直板机和隔离真实HTTPS验实际交互。纯样式不写镜像断言；使用有意义的真实几何与操作验证。业务未改时不重跑旧主链，但当前小点的失败、重试、返回和账号退出清理仍需验证。
6. 采同宽、同字号、同主题、同数据、同状态原图；执行者或复核者实际逐图看。把业务结果、原生交互、视觉审查、用户确认分别记录；不增加逐点用户审批。原图数或编译成功不等于视觉通过。

## 同数据视觉比较

首组实际基准为新直板机376vp、density3.5、fontScale1；Web视口宽376 CSS px、高742px。手机题卡外宽352、扣边框与内边距后的内容宽314，三者不能混用。后续按实际窗口重取值，不照抄设备常数，也不拿440px Web图直接比较字号和换行。

- 原生图保留完整系统区域，记录真实避让；浏览器图不含系统栏。比较内容坐标时扣除明确记录的避让，展示截图仅等比例缩放，不能裁修出“通过”。
- 核对展示字体源字节与安装包字节。模拟字体/主题驱动、缺失资源及渲染重放须说明；不能写成真实登录或媒体成功。
- 本地独立headless浏览器可重放同一真实DTO，所有API/外部资源默认拦截；题图用显式登记且核对哈希的同一图片字节重放，分别记录Web重放与Native真实加载。无图截图不能证明图片还原。不要占用用户个人浏览器逐题抄文字。Web源码与后端仓库仍只读，Vite缓存留本仓private。
- 保留产物、runtime、源码/采集器、输入DTO、PNG和报告的哈希绑定。运行中不改已冻结采集器；失败保留incomplete，后续用新报告/目录，不拼接旧计数。
- 几何断言按实际density处理物理像素舍入，公开保留原始测量值，不用代码中的目标尺寸冒充实测。

首组工具：`scripts/device-ui-parity-sample.py`、`capture-web-ui-sample.py`和`serve-ui-parity-sample.py`。它们是侧栏/Rank窄样板，不是玩法全链通用验收器。先看`--help`，新小点按实际页面适配，不静默放宽守卫或假设旧预览场次仍未入场。

## 已确认的具体边界

- 侧栏：单行小星标＋“冒险者护照”＋关闭；不额外显示“冒险者菜单”。首组保留中段现有样式，正常直板机退出初始可见；短窗口和大字号保留滚动，不据普通字号结果推定已验。
- Rank：官方标题中等级文字下保留真实间距，标题高度预算一起调整；不加独立实心背景块。首组10vp预算实测34px/3.5=9.714vp，按一物理像素舍入记录。
- 答题顶栏：题卡上缘到顶栏下缘时收起；隐藏后仅回到页顶恢复。小幅反向滚动、触底不展示，系统状态栏始终保留。不要直接采用行为不同的`bindToScrollable`。
- 题面：本轮图片范围包括结构化题图、选择图与正文内嵌图的显示、点击查看、同组多图索引及关闭/返回；图片缩放等官方能力若无法保留既有交互，完成能力核验后再提出具体差异，不静默省略。视频、BGM及线索演出后续拆片。`hideTitle`按level override优先于session，保留false/缺失区别；不显示无题名占位。
- 图片失败：用户于2026-11-05明确选择小尺寸原生“图片加载失败，重新加载”动作，保留答案，不增加大占位；这是已批准的Web差异，后续无需重复询问。
- 已发现的玩法偏差：重复场次标题/进度，手机字级/间距，题卡内双线/四角，整框登录式答题输入，额外Radio圆点，反馈与重连层级。各自逐点还原并验证，不能因列入清单就标已完成。

完整题库统计见`artifacts/validation/ui-parity-20261104/content-ui-coverage.json`；原始快照和真实案例索引仅private。答案、受保护媒体URL、玩家关系与口令不进入skill、公开样例或报告。生产内容只读授权不等于生产入场/答题授权。
